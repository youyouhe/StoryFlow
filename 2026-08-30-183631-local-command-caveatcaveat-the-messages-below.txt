     续写场景转换控制（Scene-Transition Awareness for CONTINUE）

     Context

     当前 CONTINUE（续写）模式把生成内容直接追加到剧本末尾，AI
     在续写中途可能自行插入新 [SCENE]
     场景标题，也可能在同一场景里闷头写下去——场景何时转换完全由 AI 
     黑箱决定，用户没有掌控权。

     实际剧作中，转场是重要的叙事节奏决策（该不该切、切到哪里、为何切），不应交
     给 AI 随机决定。本方案让 AI 在续写前先做"场景转换判断"并给出建议，用户确认
     后再续写，把转场决策权交还用户。

     已与用户确认的决策：
     - AI 建议 + 用户确认：AI 每次续写前判断"该继续当前场景 /
     该转场"，给出判断与动机；用户在 AI
     面板看到建议并选择采纳或否决，保留人工最终决定权。
     - 转场时给"标题 + 动机"：AI 建议转场时一并给出新场景标题（INT./EXT. 
     LOCATION - TIME）和一两句转场动机。

     设计：两段式续写流程

     把 CONTINUE 从"一次调用直出剧本块"改为两步：

     1. 判断步（新）：调用新函数 decideSceneTransition，输出结构化判断：action: 
     'continue'|'transition'、reason、（仅 transition 时）sceneHeading。
     2. 续写步：用户确认后，按判断结果调 generateContinuation，并把"是否允许转场
     / 目标场景标题"作为指令注入，约束 AI 行为。

     判断结果展示在 AI 面板（CONTINUE 模式），用户三选一：
     - 继续当前场景 → 调续写，强制"不要转场，只在当前场景内推进"
     - 采纳转场（仅当 AI 建议 transition）→
     调续写，指令含"以给定场景标题开头的新场景"
     - 丢弃 → 关闭面板

     ▎ 范围控制：IDEAS / REWRITE / STORYBOARD 保持现有一次性调用模式不变，只有 
     ▎ CONTINUE 走两步。

     数据与状态

     扩展 AIState（types.ts:78-82），新增一个可空字段持有判断结果（不污染剧本数
     据模型，不开新 useState）：

     export interface SceneTransitionDecision {
       action: 'continue' | 'transition';
       reason: string;
       sceneHeading?: string;   // 仅 transition
     }

     export interface AIState {
       isLoading: boolean;
       suggestion: string | null;
       error: string | null;
       decision: SceneTransitionDecision | null;  // 新增：续写前的判断中间态
     }

     CONTINUE 流程状态机：
     - 进入 CONTINUE → 自动跑判断步 → aiState.decision 填充，suggestion 仍为
     null → 面板显示判断卡 + 三按钮
     - 用户点"继续/采纳" → 跑续写步 → suggestion 填充 → 显示续写结果（沿用现有
     Insert 流程）
     - 任何时候"丢弃"/切换 mode tab → 清空 decision 和 suggestion

     用 aiState.decision 而非独立 useState：现有代码所有 setAIState({...})
     调用点都把 suggestion/error 一起重置，把 decision 也纳入可保证它跟
     loading/suggestion 同步清空，避免遗留脏状态（这是上次会话教训——EditorBlock
     回落语义没传导到调用方就是这个坑）。

     suggestion 非空时立即 acceptAISuggestion()。两步式下需改成：仅当 suggestion
     非空 且 decision 已被消费（即 decision === null 或新增一个 phase
     标记）时才 auto-accept。最简改法：auto-accept effect 条件加 && 
     !aiState.decision——判断步产出 decision 时不触发自动插入；续写步产出
     suggestion 且 decision 已清空时才触发。续写步在 setAIState 时同时把
     decision 置 null。

  关键设计点

  1. JSON 模式：判断步要求严格 JSON 输出。callAIProvider 的 jsonMode 对 Gemini
  注入 responseMimeType: 'application/json'、对 DeepSeek 注入 response_format: 
  {type:'json_object'}。默认 false，不影响现有三个函数。
  2. 容错降级：判断步失败（API 错误/JSON 解析失败）→ 降级为 {action:'continue', 
  reason:...}，用户仍可点"继续当前场景"完成续写，不阻塞创作。
  3. 用户否决权：即便 AI 建议转场，"继续当前场景"按钮始终可见——用户可无视建议强
  行在原场景续写。转场标题用 <input> 可编辑后再采纳。
  4. state 同步：用 aiState.decision 而非独立 useState，所有 setAIState({...})
  调用点统一带 decision，避免切换 mode/丢弃时残留脏状态（上次 EditorBlock
  回落语义没传导的坑）。
  5. autoAcceptAI 兼容：effect 条件加 !aiState.decision——判断步产出 decision
  时不触发自动插入，只有续写步产出 suggestion（decision 已清空）才自动接受。
  6. lyrics 短路：歌词模板无场景概念，CONTINUE 跳过判断步直接续写，维持原行为。
